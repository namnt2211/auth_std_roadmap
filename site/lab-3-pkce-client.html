Lab 3 — Client Authorization Code + PKCE

Bạn viết một console app để alice đăng nhập bằng trình duyệt thật (system browser), nhận code qua một “server tí hon” trên máy (loopback redirect), đổi lấy token và gọi API. Trên đường đi, bạn tự nhìn thấy code_challenge, state, nonce và so sánh ID token với access token bằng dữ liệu thật.

⏱ ~30 phút 📘 Lab · Hands-on OAuth/OIDC với ASP.NET Core
📖 Thuật ngữ trong bài
System browser
Trình duyệt mặc định của máy (Edge, Chrome…), không phải khung web nhúng trong app. App không đọc được mật khẩu user gõ vào đó.
Loopback redirect
Redirect URI trỏ về chính máy mình (http://127.0.0.1:7890/); app mở một listener ở cổng đó để “hứng” code.
Authorization request
URL app mở trên trình duyệt tới /auth của Keycloak, chứa client_id, scope, redirect_uri, PKCE, state, nonce.
Authorization code
Mã dùng một lần, sống rất ngắn, Keycloak trả về qua redirect; app đổi nó lấy token.
code_verifier / code_challenge
Chuỗi bí mật ngẫu nhiên app giữ / hash SHA-256 của chuỗi đó gửi trước cho Keycloak (PKCE).
state
Giá trị ngẫu nhiên app gửi đi và phải nhận lại y nguyên ở callback — chống giả mạo callback.
nonce
Giá trị ngẫu nhiên app gửi đi và phải thấy lại trong ID token — gắn ID token với lần đăng nhập này.
Front channel / back channel
Front = đi qua trình duyệt (URL, redirect — người khác có thể thấy). Back = app gọi thẳng server (token endpoint), trình duyệt không thấy.
OidcClient
Thư viện Duende.IdentityModel.OidcClient lo phần sinh PKCE/state, dựng URL, đổi code lấy token.
PAR
Pushed Authorization Requests: app POST tham số lên Keycloak trước, URL trên trình duyệt chỉ còn request_uri.

Lab 3 — Client dùng Authorization Code + PKCE

Must⏱ 30 phút

(a) Mục tiêu

Viết một console app .NET (có thể chuyển sang WPF) đăng nhập alice qua system browser + loopback redirect, dùng thư viện Duende.IdentityModel.OidcClient (trước đây tên IdentityModel.OidcClient). Tự bắt và đọc từng gói tin của flow; so sánh ID token với access token; gọi API.

Nói đơn giản PKCE giống xé đôi một tấm vé: app giữ nửa bí mật (code_verifier), chỉ gửi trước cho Keycloak “dấu vân tay” của nửa đó (code_challenge = SHA-256 của verifier). Khi đổi code lấy token, app phải đưa nửa vé thật ra; kẻ trộm chỉ nhặt được code trên đường redirect thì không có nửa vé nên không đổi được. state là “số thứ tự” để app biết phản hồi quay về đúng là của lần đăng nhập mình khởi tạo. nonce là “mã niêm phong” app gửi đi và phải thấy lại y nguyên bên trong ID token. Giới hạn của phép so sánh: verifier không bị “xé” thật — challenge là hash một chiều của nó.

(b) Yêu cầu / đề bài

  1. Console app DemoClient mở trình duyệt mặc định, alice đăng nhập, app nhận code qua http://127.0.0.1:7890/, đổi lấy token.
  2. Ghi lại (bằng console log + DevTools/Fiddler): authorization request (code_challenge, code_challenge_method, state, nonce, redirect_uri, scope), callback (code, state), token response.
  3. Decode ID token và access token, điền bảng so sánh aud, azp, nonce, scope.
  4. Gọi /me và /orders của DemoApi bằng access token → cả hai 200.
  5. Nộp: ghi chú/ảnh chụp request–response của Authorization Code + PKCE (Deliverable 3, Core) + source code client.

  3. Dán Program.cs và tạo thêm Loopback.cs (hai file, cùng thư mục DemoClient).

    Code chạy theo đúng 7 bước đánh số trong comment, khớp với sequence diagram ở trên: (1) sinh nonce → (2) OidcClient sinh state + PKCE và dựng URL → (3) mở listener rồi mở trình duyệt → (4) nhận callback → (5) kiểm tra state, đổi code lấy token → (6) kiểm tra nonce, in bảng so sánh claim, lưu token ra file → (7) gọi API.

    using System.Diagnostics;
using System.Net.Http.Headers;
using System.Security.Cryptography;
using System.Text;
using System.Text.Json;
using Duende.IdentityModel.Client;      // Parameters
using Duende.IdentityModel.OidcClient;  // OidcClient, OidcClientOptions

const string Authority   = "http://localhost:8080/realms/demo";
const string RedirectUri = "http://127.0.0.1:7890/";   // PHẢI khớp tuyệt đối với Keycloak
const string ApiBase     = "http://localhost:5005";

var options = new OidcClientOptions
{
    Authority   = Authority,
    ClientId    = "demo-client",                       // public client: KHÔNG có secret
    RedirectUri = RedirectUri,
    Scope       = "openid profile email orders.read",  // orders.read -> aud demo-api
    DisablePushedAuthorization = true,                  // [LAB] để thấy tham số trên URL
    LoadProfile = false                                 // không gọi userinfo, giữ output gọn
};
// Ghi chú: mặc định OidcClient KHÔNG kiểm tra chữ ký ID token (Policy.RequireIdentityTokenSignature = false)
// vì ID token nhận trực tiếp từ token endpoint. Production nên dùng HTTPS và cân nhắc gắn IdentityTokenValidator.
var oidc = new OidcClient(options);

// 1) nonce do ta tự sinh và gửi kèm
var nonce = Base64Url(RandomNumberGenerator.GetBytes(16));
var extra = new Parameters();
extra.Add("nonce", nonce);

// 2) Chuẩn bị: OidcClient sinh state + code_verifier + code_challenge và dựng URL
var state = await oidc.PrepareLoginAsync(extra);
if (state.IsError) { Console.WriteLine($"Lỗi chuẩn bị: {state.Error} {state.ErrorDescription}"); return; }

Console.WriteLine("=== AUTHORIZATION REQUEST ===");
Console.WriteLine(state.StartUrl);
Console.WriteLine($"state         = {state.State}");
Console.WriteLine($"code_verifier = {state.CodeVerifier}  (bí mật - KHÔNG nằm trong URL)");
Console.WriteLine($"nonce         = {nonce}");

// 3) Mở listener loopback TRƯỚC khi mở browser (lớp Loopback ở file Loopback.cs bên dưới).
//    Gọi hàm là listener chạy ngay; ta giữ Task lại và await SAU khi đã mở browser.
var waitForCallback = Loopback.WaitForCallbackAsync(new Uri(RedirectUri).Port);

Process.Start(new ProcessStartInfo(state.StartUrl) { UseShellExecute = true });
Console.WriteLine("\nĐã mở trình duyệt, đang chờ callback...");

// 4) Nhận callback từ browser: phần "/?state=...&code=..." của URL
var callback = await waitForCallback;
Console.WriteLine("\n=== CALLBACK ===");
Console.WriteLine("http://127.0.0.1:7890" + callback);

// 5) Kiểm tra state + đổi code lấy token (gửi code_verifier)
var result = await oidc.ProcessResponseAsync(callback, state);
if (result.IsError) { Console.WriteLine($"Lỗi: {result.Error} {result.ErrorDescription}"); return; }

Console.WriteLine("\n=== TOKEN RESPONSE (raw) ===");
Console.WriteLine(result.TokenResponse.Raw);

// 6) Kiểm tra nonce bằng tay + so sánh claim
var idPayload = DecodePayload(result.IdentityToken);
var atPayload = DecodePayload(result.AccessToken);
var nonceInToken = idPayload.TryGetProperty("nonce", out var n) ? n.GetString() : null;
Console.WriteLine($"\nnonce khớp? {nonceInToken == nonce}");

Console.WriteLine("\n=== SO SÁNH ===");
foreach (var claim in new[] { "aud", "azp", "nonce", "scope", "typ", "sub", "iss" })
    Console.WriteLine($"{claim,-6} | ID token: {Show(idPayload, claim),-40} | Access token: {Show(atPayload, claim)}");

// Lưu token ra file để dùng ở Lab 2 (kịch bản 5) và Lab 4 (refresh). CHỈ LAB.
Directory.CreateDirectory("tokens");
File.WriteAllText("tokens/id_token.txt", result.IdentityToken);
File.WriteAllText("tokens/access_token.txt", result.AccessToken);
File.WriteAllText("tokens/refresh_token.txt", result.RefreshToken ?? "");

// 7) Gọi API
using var api = new HttpClient { BaseAddress = new Uri(ApiBase) };
api.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", result.AccessToken);
foreach (var path in new[] { "/me", "/orders" })
{
    var resp = await api.GetAsync(path);
    Console.WriteLine($"\nGET {path} -> {(int)resp.StatusCode} {resp.StatusCode}");
    Console.WriteLine($"WWW-Authenticate: {resp.Headers.WwwAuthenticate}");
    Console.WriteLine(await resp.Content.ReadAsStringAsync());
}

// ---------- helpers ----------
static string Base64Url(byte[] bytes) =>
    Convert.ToBase64String(bytes).TrimEnd('=').Replace('+', '-').Replace('/', '_');

static JsonElement DecodePayload(string jwt)
{
    var p = jwt.Split('.')[1].Replace('-', '+').Replace('_', '/');
    p = p.PadRight(p.Length + (4 - p.Length % 4) % 4, '=');
    return JsonDocument.Parse(Convert.FromBase64String(p)).RootElement.Clone();
}

static string Show(JsonElement e, string name) =>
    e.TryGetProperty(name, out var v) ? v.ToString() : "(không có)";

    Thêm file Loopback.cs cùng thư mục — một “web server” tí hon chỉ nghe 127.0.0.1:7890 để nhận đúng một callback:

    using System.Net;
using System.Net.Sockets;
using System.Text;

// Vì sao TcpListener mà không phải HttpListener? Trên Windows, HttpListener chạy qua http.sys;
// prefix http://127.0.0.1:port/ có thể bị "Access is denied" nếu chưa đăng ký URL ACL (netsh, cần admin).
// TcpListener chỉ mở socket trên 127.0.0.1 -> không cần quyền đặc biệt.
public static class Loopback
{
    public static async Task<string> WaitForCallbackAsync(int port, CancellationToken ct = default)
    {
        var listener = new TcpListener(IPAddress.Loopback, port);
        listener.Start();   // chạy ngay khi hàm được gọi (trước await đầu tiên)
        try
        {
            while (true)
            {
                using var client = await listener.AcceptTcpClientAsync(ct);
                try
                {
                    using var stream = client.GetStream();
                    var reader = new StreamReader(stream, Encoding.ASCII);
                    // Dòng đầu của HTTP request, ví dụ: "GET /?state=...&code=... HTTP/1.1"
                    var requestLine = await reader.ReadLineAsync(ct);
                    while (!string.IsNullOrEmpty(await reader.ReadLineAsync(ct))) { } // bỏ qua các header

                    var parts = requestLine?.Split(' ');
                    var target = parts is { Length: >= 2 } ? parts[1] : "";
                    var isCallback = target.StartsWith("/?");

                    var body = Encoding.UTF8.GetBytes(isCallback
                        ? "<html><body><h3>Đăng nhập xong. Bạn có thể đóng tab này.</h3></body></html>" : "");
                    var head = Encoding.ASCII.GetBytes(
                        $"HTTP/1.1 {(isCallback ? "200 OK" : "404 Not Found")}\r\n" +
                        $"Content-Type: text/html; charset=utf-8\r\nContent-Length: {body.Length}\r\nConnection: close\r\n\r\n");
                    await stream.WriteAsync(head, ct);
                    await stream.WriteAsync(body, ct);

                    if (isCallback) return target;   // request khác (favicon...) -> 404, chờ tiếp
                }
                catch (IOException) { /* browser đóng kết nối sớm -> bỏ qua, chờ request tiếp */ }
            }
        }
        finally
        {
            listener.Stop();
        }
    }
}

    using System.Diagnostics;
using Duende.IdentityModel.OidcClient.Browser;

public sealed class LoopbackBrowser : IBrowser
{
    public async Task<BrowserResult> InvokeAsync(BrowserOptions options, CancellationToken ct = default)
    {
        using var cts = CancellationTokenSource.CreateLinkedTokenSource(ct);
        cts.CancelAfter(options.Timeout);                        // mặc định 5 phút

        // Dùng lại Loopback.cs: listener bắt đầu nghe NGAY, trước khi mở browser
        var wait = Loopback.WaitForCallbackAsync(new Uri(options.EndUrl).Port, cts.Token);
        Process.Start(new ProcessStartInfo(options.StartUrl) { UseShellExecute = true });

        try
        {
            var callback = await wait;                          // "/?state=...&code=..."
            return new BrowserResult { ResultType = BrowserResultType.Success, Response = callback };
        }
        catch (OperationCanceledException)
        {
            return new BrowserResult { ResultType = BrowserResultType.Timeout };
        }
    }
}
// Dùng: options.Browser = new LoopbackBrowser();  var result = await oidc.LoginAsync();

Cách đọc output trên: URL ở khối REQUEST có code_challenge nhưng không có code_verifier; state ở CALLBACK trùng với state ở REQUEST; code chỉ xuất hiện ở CALLBACK; token chỉ xuất hiện ở TOKEN RESPONSE (back channel).

(f) Câu hỏi tự kiểm tra

Vì sao code_verifier không bao giờ xuất hiện trên URL?

URL đi qua browser, lịch sử, log proxy, có thể bị app khác chặn redirect. Chỉ code_challenge (hash một chiều) đi qua front channel; verifier chỉ đi qua back channel (POST tới token endpoint). Kẻ trộm code không có verifier thì không đổi được token.

state và nonce chống lại điều gì, khác nhau ra sao?

state gắn callback với request đã gửi → chống CSRF/login injection ở redirect (client kiểm tra trước khi đổi code). nonce nằm trong ID token → chống replay ID token, gắn token với phiên đăng nhập của client (kiểm tra sau khi nhận token).

Vì sao không cần client_secret khi đổi code?

demo-client là public client; PKCE đóng vai “bằng chứng” rằng bên đổi code là bên đã khởi tạo flow.
