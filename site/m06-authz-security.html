Module 06 — Authorization & Authentication Security

Đăng nhập thành công mới là một nửa câu chuyện. Nửa còn lại: bạn được làm gì (authorization — phân quyền), API kiểm tra quyền ở bước nào, và kẻ gian có những mánh nào để chiếm login, session (phiên đăng nhập) hay token — cùng cách chặn từng mánh.

⏱ Full 2 giờ · Core 1.5 giờ (đọc lướt ABAC/ACL/ReBAC) 📥 Input: M01–M05, token/session/scope ➡️ Tiếp theo: Module 07
Sau module này bạn sẽ
  • Phân biệt permission, role, policy, scope, claim
  • So sánh được RBAC, ABAC, ACL, ReBAC và biết khi nào dùng
  • Vẽ được pipeline phân quyền trong API và trả đúng 401 / 403
  • Viết policy + resource-based authorization trong ASP.NET Core
  • Nhận diện CSRF, XSS, AiTM, IDOR/BOLA, MFA fatigue… và cách phòng vệ
  • Áp dụng chính sách mật khẩu theo NIST SP 800-63B-4
  • Chọn nơi lưu token trong browser và hiểu vì sao nên dùng BFF
Nói đơn giản — cả module trong một câu chuyện Bảo vệ tòa nhà đã kiểm tra CCCD và phát thẻ cho bạn (authentication — đã học ở M01–M05). Module này là phần còn lại: thẻ của bạn mở được cửa nào (authorization), và kẻ gian có những mánh gì để mượn thẻ, làm giả thẻ hay lừa bạn quẹt thẻ hộ (threats).
🎯 Mục tiêu module
  1. Hiểu authorization là một bước riêng, đứng sau authentication: token hợp lệ (“biết bạn là ai”) chưa có nghĩa là được phép (“được làm việc này”).
  2. Lần theo được một request đi vào API: xác minh token → kiểm tra scope/role → kiểm tra quyền trên đúng bản ghi → cho phép hoặc từ chối (trả mã lỗi nào).
  3. Nhận ra các lỗi bảo mật hay gặp (CSRF, XSS, AiTM, lộ token, IDOR…) và nói được cách giảm thiểu cho từng lỗi.

Input trước module

Bạn sẽ học dễ hơn nếu đã nắm những thứ dưới đây. Chưa chắc phần nào thì mở lại link tương ứng trước khi bắt đầu:

  • Đã học Module 01–05 và làm Lab (đặc biệt Lab 2 — API kiểm tra JWT, code của module này mở rộng từ đó).
  • Phân biệt được 401 và 403 (M01), session/cookie (M02), access token, claim, scope (M02) và các flow OAuth/OIDC (M03).
  • Biết sơ về middleware trong ASP.NET Core: chuỗi bước mà mọi request đi qua (xác thực, phân quyền…) trước khi tới code endpoint.
💡 Ví dụ xuyên suốt: “Order API” của công ty bán lẻ
  • Order API (ASP.NET Core, aud = demo-api) quản lý đơn hàng. Mỗi đơn có OwnerId (người tạo), Department (phòng ban) và Amount.
  • An (Employee, phòng Sales-HN) tạo đơn. Bình (Manager, phòng Sales-HN) duyệt đơn của phòng mình. Chi (Employee, phòng Sales-HCM).
  • Client: SPA nội bộ và app WPF (lấy token qua Authorization Code + PKCE, xem M03). Một worker service đồng bộ dữ liệu bằng Client Credentials.
Đây chính là API ở Lab 2, được mở rộng thêm phần phân quyền. Ở một số bảng “Phân biệt dễ nhầm”, ví dụ dùng lại hệ thống Kaopiz HR quen thuộc từ M01–M02 (hr-web, hr-api, nhân viên An xem bảng lương).

Các bài trong module

Học lần lượt từng bài (mỗi bài một lần ngồi), cuối cùng làm trang Ôn tập & Quiz. Thanh điều hướng đầu mỗi trang cho biết bạn đang ở đâu trong module.

  1. Bài 6.1 — Mô hình phân quyền · ~25 phút
    Permission, role, policy, scope, claim; RBAC, ABAC, ACL, ReBAC và policy engine.
  2. Bài 6.2 — Authorization trong API · ~20 phút
    Pipeline quyết định, 401 vs 403, deny by default, IDOR/BOLA và code policy + resource-based authorization.
  3. Bài 6.3 — CSRF, XSS & session fixation · ~25 phút
    Ba tấn công web kinh điển nhắm vào session và cookie — cơ chế và cách phòng.
  4. Bài 6.4 — MFA fatigue, AiTM, JWT confusion & enumeration · ~15 phút
    Các tấn công vượt MFA, lỗi validate JWT, account enumeration và recovery flow.
  5. Bài 6.5 — Mật khẩu (NIST), token storage & best practices · ~15 phút
    Chính sách mật khẩu theo NIST SP 800-63B-4, lưu token trong browser ở đâu, và checklist best practices.
  6. Ôn tập & Quiz · ~20 phút
    Hiểu lầm cần tránh, tóm tắt, deliverables, knowledge check và quiz trắc nghiệm.
