Module 03 — OAuth 2.0, OAuth 2.1 & OpenID Connect

Module trọng tâm của lộ trình. Câu hỏi xuyên suốt: làm sao để một app được dùng dữ liệu của bạn ở dịch vụ khác mà không cần biết mật khẩu của bạn? OAuth trả lời bằng cách cấp cho app một “vé” có giới hạn (access token) — gọi là ủy quyền (delegated authorization). OpenID Connect (OIDC) xây thêm lên OAuth để trả lời câu hỏi thứ hai: người đang dùng app là ai? (ID token). Bạn sẽ học các flow chính, vì sao vài flow cũ bị bỏ, và các cơ chế chống tấn công đi kèm.

⏱ Full 3 giờ · Core 2.5 giờ 📥 Input: M01, M02 🧪 Thực hành: Lab 1–3 ➡️ Tiếp theo: Lab
Sau module này bạn sẽ
  • Giải thích được vì sao OAuth (Open Authorization) ra đời: để app khác truy cập dữ liệu của bạn mà không cần mật khẩu của bạn.
  • Kể tên 4 vai trò: Resource Owner, Client, Authorization Server, Resource Server — và chỉ ra chúng trong một hệ thống thật.
  • Vẽ được Authorization Code + PKCE (cho người dùng) và Client Credentials (cho service), đọc hiểu từng HTTP request.
  • Biết state, nonce, PKCE, redirect URI validation mỗi cái chặn tấn công nào.
  • Hiểu OIDC (OpenID Connect) thêm ID token để biết “ai đang đăng nhập”, và phân biệt ID token với access token.
  • Lưu người dùng bằng iss + sub, không phải email; liên kết tài khoản social login an toàn.
🎯 Mục tiêu module Học xong, bạn tự làm được 5 việc sau:
  1. Phân biệt chắc chắn authorization (“được phép làm gì” — OAuth) và authentication (“là ai” — OIDC).
  2. Vẽ và giải thích từng bước của Authorization Code + PKCE (có người dùng) và Client Credentials (service gọi service, không có người dùng).
  3. Nói được state / nonce / PKCE / redirect URI validation mỗi cái chặn tấn công nào.
  4. Mô tả cách client kiểm tra ID token và API kiểm tra access token — không nhầm token nào dành cho ai.
  5. Định danh người dùng bằng iss + sub (không phải email).
🗺️ Nếu thấy khó, hãy đọc theo thứ tự này Bài 3.1 cho bạn “bản đồ” (ai là ai, ai nói chuyện với ai). Bài 3.2 đi từng bước một flow — đọc chậm, đối chiếu với sơ đồ. Đừng cố nhớ hết tham số ngay: mỗi HTTP request đều có bảng chú giải bên dưới, quay lại tra khi cần.
🧭 Học theo Core (2.5 giờ)? Học kỹ các mục Must. Mục Should (OAuth 2.1, Device flow, Discovery/JWKS, logout, social login & account linking) đọc lướt để biết khái niệm. Mục Nice (ROPC/Implicit, multi-tenant, On-Behalf-Of) chỉ cần biết tên, use case và “vì sao không dùng / không phải là gì”.

Input trước module

Bạn cần nắm chắc mấy thứ sau trước khi bắt đầu (chưa chắc thì xem lại link tương ứng):

  • Hoàn thành Module 01 (vai trò IdP, RP, Client, AS, RS — xem lại) và Module 02 (token, JWT, JWT validation).
  • HTTP redirect: server trả 302 + header Location: <url> và trình duyệt tự động mở URL đó. OAuth dùng cơ chế này để “chuyển” người dùng qua lại giữa app và máy chủ đăng nhập.
  • Query string (phần ?a=1&b=2 trên URL), POST body dạng form (application/x-www-form-urlencoded — cũng là a=1&b=2 nhưng nằm trong body, không hiện trên URL), header Authorization.
  • Biết JWT gồm header.payload.signature và cách kiểm tra chữ ký/claims ở mức khái niệm.
💡 Ví dụ xuyên suốt module
  • Bài toán mở đầu: app in ảnh PrintNow muốn đọc album ảnh của An trên dịch vụ lưu ảnh PhotoCloud (tên hư cấu, minh họa cho kiểu “app in ảnh đọc Google Photos”).
  • Hệ thống thực hành (khớp với Lab 1): Keycloak chạy ở http://localhost:8080, realm demo; public client demo-client (desktop/WPF, loopback redirect http://127.0.0.1:7890/); API demo-api với scope orders.read; confidential client worker (service-to-service).

Các bài trong module

Học lần lượt từng bài (mỗi bài một lần ngồi), cuối cùng làm trang Ôn tập & Quiz. Thanh điều hướng đầu mỗi trang cho biết bạn đang ở đâu trong module.

  1. Bài 3.1 — OAuth: vấn đề, vai trò & thuật ngữ · ~25 phút
    Vì sao OAuth ra đời, 4 vai trò, public vs confidential client và các endpoint chính.
  2. Bài 3.2 — Authorization Code + PKCE · ~30 phút
    Flow quan trọng nhất cho ứng dụng có người dùng — đọc từng HTTP request và hiểu PKCE chặn tấn công nào.
  3. Bài 3.3 — Client Credentials, Device flow & OAuth 2.1 · ~30 phút
    Grant cho service-to-service và thiết bị không bàn phím, refresh token grant, vì sao bỏ ROPC/Implicit, OAuth 2.1 đổi gì.
  4. Bài 3.4 — state, nonce & redirect URI · ~10 phút
    Ba cơ chế nhỏ nhưng sống còn: mỗi cái chặn tấn công nào, ví dụ login CSRF và cách validate redirect URI.
  5. Bài 3.5 — OpenID Connect & ID token · ~25 phút
    OIDC thêm lớp danh tính lên OAuth: ID token, scope/claims, UserInfo, flow đầy đủ và checklist validate ID token.
  6. Bài 3.6 — Discovery, JWKS & Logout · ~15 phút
    Metadata/JWKS, cache và key rotation; RP-initiated, front-channel và back-channel logout.
  7. Bài 3.7 — Định danh user, social login & nâng cao · ~15 phút
    Lưu user bằng iss + sub, thiết kế external login, account linking an toàn, multi-tenant và On-Behalf-Of.
  8. Ôn tập & Quiz · ~20 phút
    Hiểu lầm cần tránh, tóm tắt, deliverables, knowledge check và quiz trắc nghiệm.
