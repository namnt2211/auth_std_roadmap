Module 07 — Authentication Architecture & Practical Cases

Các module trước dạy từng giao thức riêng lẻ (OIDC, OAuth, SAML, Kerberos, WebAuthn…). Module này ghép chúng lại thành hệ thống thật: với một ứng dụng cụ thể (web, SPA, desktop, mobile, service), bạn chọn flow nào, token nằm ở đâu, ai giữ bí mật — và khi đăng nhập hỏng thì gỡ lỗi theo thứ tự nào.

⏱ Full 2 giờ · Core 45 phút (7.2, SPA/Desktop/S2S, ví dụ WPF, deliverable 1–2) 📥 Input: M01–M06 ➡️ Tiếp theo: Phụ lục
Sau module này bạn sẽ
  • Thiết kế authentication bằng 10 câu hỏi có thứ tự (ai đăng nhập, bằng app gì, bảo vệ cái gì…)
  • Chọn đúng flow cho web server, SPA, desktop, mobile, service — và nói được token nằm ở đâu trong từng kiểu
  • Giải thích được BFF (backend nhỏ giữ token thay cho SPA) và vì sao CORS không phải authN/authZ
  • Vẽ được kiến trúc WPF + ASP.NET Core Web API kèm sequence đăng nhập và gọi API
  • Hiểu vòng đời tài khoản: tạo (provisioning: JIT, SCIM) và thu hồi khi nghỉ việc (offboarding: revoke, CAE)
  • Chẩn đoán lỗi OIDC/SAML/API, phân biệt nhanh 401 vs 403 và các lỗi 401 dễ nhầm (sai aud, sai issuer, hết hạn)
  • Dùng decision matrix để chọn OIDC, SAML, Kerberos, FIDO2, RADIUS, API key
Nói đơn giản — cả module trong một câu chuyện Các module trước dạy bạn từng loại khóa (OIDC, SAML, Kerberos, passkey…). Module này giống công việc của kiến trúc sư an ninh tòa nhà: cửa chính dùng khóa gì, cửa kho dùng khóa gì, xe giao hàng (service) vào bằng thẻ gì, nhân viên nghỉ việc thì thu thẻ thế nào — và khi cửa không mở, kiểm tra theo thứ tự nào.

Input trước module

Module này không dạy giao thức mới — nó dùng lại kiến thức cũ. Trước khi bắt đầu, bạn nên:

  • Hoàn thành M01–M06 và Lab. Tối thiểu cần nắm chắc: Authorization Code + PKCE, ID token vs access token, cách API kiểm tra JWT và 401 vs 403.
  • Chọn một kiến trúc thực tế của team hoặc một case study giả định để áp dụng. Trang này dùng hai ví dụ xuyên suốt: hệ thống HR nội bộ Kaopiz HR (hr-web, hr-api, Keycloak realm kaopiz) và WPF + ASP.NET Core Web API (“Order API” của M06).
  • Biết vẽ sequence diagram (sơ đồ ai gọi ai theo thời gian) hoặc component diagram (sơ đồ các khối hệ thống) cơ bản.

Ba cặp thuật ngữ dùng xuyên suốt module:

  • Public client: ứng dụng không giữ được bí mật (SPA, desktop, mobile) vì code chạy trên máy người dùng — ai cũng mở ra xem được. Confidential client: ứng dụng chạy trên server, giữ được client secret/khóa (web server, BFF, service).
  • Trust boundary (ranh giới tin cậy): đường phân chia giữa vùng bạn kiểm soát (server của bạn) và vùng không kiểm soát (browser, máy người dùng, mạng Internet). Mọi dữ liệu đi qua ranh giới này đều phải được kiểm tra.
  • Resource Server (RS): API giữ dữ liệu, kiểm tra access token. IdP (Identity Provider): hệ thống đăng nhập và phát hành token (Keycloak, Entra ID…).
