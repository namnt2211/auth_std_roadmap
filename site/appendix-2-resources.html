C. Nội dung nâng cao chưa đào sâu trong 15 giờ Nice

Nói đơn giản Phần lớn chủ đề dưới đây trả lời một trong ba câu hỏi: (1) làm sao để token bị trộm vẫn vô dụng (DPoP, mTLS), (2) làm sao để yêu cầu đăng nhập không bị sửa giữa đường (PAR, JAR, JARM), (3) làm sao để quản lý danh tính ở quy mô lớn (Federation, SCIM, IGA, CAE). Chỉ cần nhớ câu hỏi, chi tiết tra spec khi cần.

Để giữ đúng giới hạn thời lượng, các chủ đề sau chỉ cần biết tên, biết nó giải quyết vấn đề gì. Đây không phải các chủ đề không quan trọng; chúng được tách ra vì cần thời gian riêng để học đúng chiều sâu.

Gợi ý kịch bản demo (30 phút, buổi 2)

  1. Login thành công (Auth Code + PKCE): mở DevTools/Fiddler, chỉ ra code_challenge, state, redirect về redirect_uri, rồi đổi code lấy token.
  2. Giải mã access token: chỉ ra iss, aud, exp, scope; nhấn mạnh “ký ≠ bí mật”.
  3. Gọi API 4 kịch bản lỗi: không token → 401; sai aud → 401; token hết hạn → 401 kèm WWW-Authenticate; thiếu scope → 403. (bảng lỗi Lab)
  4. Gửi ID token thay access token → bị từ chối; giải thích vì sao.
  5. Bật lại MapInboundClaims → sub “biến mất”; liên hệ lỗi .NET số 2.
  6. (Tùy chọn) Passkey trên trang demo WebAuthn, hoặc thu hồi phiên ở Keycloak và quan sát refresh token bị từ chối.
✅ Mẹo demo Chuẩn bị sẵn token đã hết hạn và token sai audience (ghi vào file .http) để không phụ thuộc mạng/IdP lúc trình bày; có ảnh chụp màn hình dự phòng cho từng bước.

G. Tài liệu tham khảo chính thống

Ưu tiên specification và tài liệu của tổ chức tiêu chuẩn/nhà cung cấp nền tảng. Trạng thái dưới đây được kiểm tra tại thời điểm 11/2026.

📝 Cập nhật so với roadmap gốc
  • OAuth 2.0 for Browser-Based Applications không còn là Internet-Draft: đã ban hành thành RFC 10017 (BCP 212, 8/2026).
  • Web Authentication Level 3 đã là W3C Recommendation (25/8/2026), kế nhiệm Level 2.
  • OAuth 2.1 vẫn là Internet-Draft (draft-ietf-oauth-v2-1-17, 10/2026) — chưa có số RFC.
  • NIST SP 800-63-4 đã final (7/2025), thay thế bộ 800-63-3.

✅ Nguyên tắc tra cứu Khi có khác biệt giữa bài viết tổng quan và specification, ưu tiên specification hiện hành và tài liệu chính thức của nhà cung cấp đang triển khai. Kiểm tra trạng thái (RFC/Draft/Recommendation, có bị “Updated by/Obsoleted by” không) trước khi dùng làm tiêu chuẩn triển khai production.

Tóm tắt nhanh

  • Trong ASP.NET Core: UseAuthentication() phải chạy trước UseAuthorization(); CORS đặt trước cả hai.
  • Web app thường dùng Cookie + OIDC; Web API dùng JwtBearer với Authority + Audience.
  • Challenge = “chưa đăng nhập” (401/redirect login); Forbid = “thiếu quyền” (403). Phản hồi cụ thể do scheme quyết định.
  • Đặt MapInboundClaims = false để giữ nguyên tên claim gốc (sub, scp, roles…); claim scope của Keycloak vốn không bị đổi tên nhưng là chuỗi nhiều scope cách nhau dấu cách.
  • Chạy nhiều instance → chia sẻ Data Protection key ring; không bao giờ tắt kiểm tra aud/iss ở production.
  • ASP.NET Core Identity băm mật khẩu bằng PBKDF2-HMAC-SHA512 (100.000 vòng mặc định) và hỗ trợ passkey từ .NET 10.
  • Chủ đề nâng cao (DPoP, PAR, RAR, Token Exchange, FAPI 2.0…) chỉ cần biết tên và vấn đề chúng giải quyết.
  • Bộ tài liệu cuối khóa = 9 tài liệu + demo repo, gom từ deliverable các module.
  • Mốc sẵn sàng đứng lớp: ≥ 12/16 và không có điểm 0 ở OAuth/OIDC, token, security, Lab.
  • Trạng thái 11/2026: OAuth 2.1 vẫn là draft; browser-based apps đã là RFC 10017; WebAuthn L3 đã là Recommendation; NIST 800-63-4 đã final.
