Lab — Hands-on OAuth/OIDC với ASP.NET Core

Ở Module 03 bạn mới vẽ flow trên giấy. Ở đây bạn dựng chúng chạy thật trên máy mình: Keycloak cấp token, một Web API ASP.NET Core kiểm tra token, một console app đăng nhập bằng Authorization Code + PKCE, và một “worker” tự xin token bằng Client Credentials. Bạn sẽ đọc request, response và token thật, rồi cố tình làm hỏng từng chỗ để hiểu vì sao API trả 401 hay 403.

⏱ Full 2 giờ · Core 1.5 giờ (Lab 1–3) 📥 Input: hoàn thành M01–M03 🧰 .NET 10 LTS · Docker · Keycloak 26.x ➡️ Tiếp theo: Module 04
Sau module này bạn sẽ
  • Tự dựng một IdP (Keycloak) với realm, user, client public/confidential, client scope và audience — biết vì sao từng cấu hình tồn tại.
  • Viết một ASP.NET Core Web API xác minh access token (JWT) và tái hiện được ít nhất 6 lỗi 401/403, đọc được header WWW-Authenticate và log IDX10xxx.
  • Viết một console app .NET đăng nhập bằng Authorization Code + PKCE qua system browser và loopback redirect, tự bắt được code_challenge, state, nonce.
  • Phân biệt ID token và access token bằng dữ liệu thật (aud, azp, nonce, scope).
  • Dùng Client Credentials, quan sát refresh token rotation, gọi introspection và revocation endpoint.
  • (Nice) Đọc một SAML Response thật bằng SAML-tracer.
📦 Code mẫu hoàn chỉnh Toàn bộ code của lab (solution AuthLab: DemoApi, DemoClient, DemoClientBrowser, .NET 10) có trong thư mục lab/ của repo. Nên tự gõ theo hướng dẫn trước, chỉ dùng code mẫu để đối chiếu khi bị kẹt.
🎯 Mục tiêu của Lab (theo roadmap) Biến các flow đã vẽ ở Module 03 thành hệ thống chạy được. Tập đọc request, response và token thật thay vì chỉ học qua sơ đồ. Kết quả lab cũng là demo cho buổi chia sẻ và là nguồn dữ liệu cho troubleshooting guide ở Module 07.
🧭 Cách đọc trang này Mỗi lab có 6 phần cố định: (a) Mục tiêu → (b) Yêu cầu/đề bài (bạn phải đạt được gì, nộp gì) → (c) Hướng dẫn từng bước (mỗi bước: làm gì – vì sao – kiểm tra đã đúng chưa) → (d) Kết quả mong đợi → (e) Lỗi thường gặp → (f) Câu hỏi tự kiểm tra. Hãy đọc phần (b) trước để biết “đích đến”, rồi mới làm (c).

📖 Thuật ngữ trong bài
IdP (Identity Provider)
Hệ thống xác thực người dùng và phát hành token. Trong lab là Keycloak.
Realm (Keycloak)
Một “không gian” riêng chứa user, client, cấu hình. Mỗi realm có issuer riêng, ví dụ http://localhost:8080/realms/demo.
Client
Ứng dụng được đăng ký với Keycloak để xin token. Public client không giữ được bí mật (app desktop/mobile/SPA); confidential client chạy trên server, giữ được client_secret.
Access token
“Thẻ” client đưa cho API để được gọi; sống ngắn (Keycloak mặc định 5 phút).
ID token
“Biên nhận đăng nhập” gửi cho client, cho biết ai vừa đăng nhập — không dùng để gọi API (so sánh).
Scope
Phạm vi quyền client xin, ví dụ orders.read = “được đọc đơn hàng”.
Audience (aud)
Token này dành cho ai — API nào được phép nhận nó. DemoApi chỉ nhận token có aud chứa demo-api.
JWKS và kid
JWKS (JSON Web Key Set) là danh sách khóa công khai của IdP để kiểm tra chữ ký JWT; kid (key ID) ghi trong header JWT để biết dùng khóa nào.

🔒 Lưu ý bảo mật (bắt buộc đọc)
  • Không dán token của môi trường production vào công cụ decode online (jwt.io, jwt.ms…). Token lab trên localhost thì không sao. Trang này có sẵn một bộ decode chạy hoàn toàn trong trình duyệt.
  • Lab dùng HTTP và RequireHttpsMetadata = false chỉ cho localhost. Production bắt buộc HTTPS.
  • start-dev của Keycloak, admin admin/admin, IdentityModelEventSource.ShowPII = true, và việc in token ra console — tất cả chỉ dành cho lab. Đừng để lọt lên production (xem lỗi .NET hay gặp).

Các bài trong module

Học lần lượt từng bài (mỗi bài một lần ngồi), cuối cùng làm trang Ôn tập & Quiz. Thanh điều hướng đầu mỗi trang cho biết bạn đang ở đâu trong module.

  1. Lab 1 — Cấu hình Keycloak · ~20 phút
    Dựng IdP: realm, user, client public/confidential, client scope và audience.
  2. Lab 2 — Web API xác minh JWT · ~30 phút
    ASP.NET Core Web API xác minh access token và tái hiện các lỗi 401/403.
  3. Lab 3 — Client Authorization Code + PKCE · ~30 phút
    Console app đăng nhập qua system browser + loopback redirect, quan sát code_challenge, state, nonce.
  4. Lab 4 — Client Credentials, refresh, introspection · ~20 phút
    Worker dùng Client Credentials, quan sát refresh token rotation, gọi introspection và revocation.
  5. Lab 5 — Đọc SAML Response · ~20 phút
    Dùng SAML-tracer để đọc một SAML Response thật.
  6. Công cụ, tổng kết & Quiz · ~15 phút
    Hiểu lầm cần tránh, tóm tắt, deliverables, knowledge check và quiz trắc nghiệm.
